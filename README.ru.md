# Как собрать

## Требования
- **JDK 17 или новее** — сборка выполняется тем JDK, под которым запускается Gradle (включая JDK 21 и JDK 25); полученный байткод нацелен на Java 17 (`--release 17`). Без привязки к toolchain.

## Сборка OpenAllatori

Запустите из этой папки:

```powershell
.\gradlew.bat clean build
```

Сигнал успеха — `BUILD SUCCESSFUL`; в `build/libs/` появятся:
- `OpenAllatori-9.9.jar` — обфускатор **и** деобфускатор
- `OpenAllatori-9.9-sources.jar`

---

# Использование обфускатора

Как в оригинальном Allatori: управляется XML-конфигом.

```powershell
java -jar build\libs\OpenAllatori-9.9.jar my-config.xml
```

Важнейшее свойство — **файл журнала**: обфускатор записывает туда каждое переименование, и именно этот файл позволяет позже вернуть сборку в исходный вид:

```xml
<property name="log-file" value="out/mapping.xml"/>
```

# Использование деобфускатора

```powershell
java -cp build\libs\OpenAllatori-9.9.jar com.allatori.deobfuscate.Deobfuscate <команда> ...
```

| Команда | Аргументы | Что делает |
|---|---|---|
| `full` | `<mapping.xml> <in.jar> <out.jar> [--remove-decryptor]` | расшифровывает строки, удаляет дешифратор, восстанавливает все имена — именно в этом порядке |
| `rename-back` | `<mapping.xml> <in.jar> <out.jar>` | восстанавливает исходные имена классов/методов/полей из маппинга |
| `decrypt-strings` | `<in.jar> <out.jar> [--remove-decryptor]` | заменяет зашифрованные строки открытым текстом |
| `restore-stacktrace` | `<mapping.xml> <in.txt> <out.txt>` | переписывает обфусцированный стек-трейс обратно в исходные имена/строки |

## Демонстрация полного цикла

```powershell
.\gradlew.bat runDemoRoundTrip
```

Компилирует крошечное демо-приложение, обфусцирует его, деобфусцирует и запускает три JAR: оригинальный, обфусцированный и деобфусцированный. Проверенный результат: деобфусцированный JAR печатает **байт-в-байт тот же вывод**, что и оригинал, создаёт **идентичные стек-трейсы** (`at com.example.demo.App.crash(App.java:31)`), а `javap -c` чисто дизассемблирует каждый класс.

## Опционально: дополнительная очистка через Recaf

Для ещё более чистого результата прогоните деобфусцированный JAR через необязательную очистку с [Recaf 4.x](https://github.com/Col-E/Recaf) и плагином RecafMCP:

1. Запустите Recaf с загруженным плагином RecafMCP (мост-сервер на `localhost:9847`).
2. Откройте деобфусцированный JAR.
3. Примените пресет трансформеров `generic_all` в несколько проходов (5 достаточно).
4. Экспортируйте JAR.

Что это даёт: удаляются оставшиеся пары `nop` от перезаписи вызовов при расшифровке строк, статические методы, которые просто возвращают константу, сворачиваются в `ldc`, мёртвые смещения уплотняются и т.д. (23 трансформера в пресете `generic_all`). Проверено на демо-цикле: вывод и стек-трейсы остаются байт-в-байт идентичными, а `javap -c` по-прежнему чисто дизассемблирует каждый класс.

# Как работает деобфускатор

Деобфускатор — точная обратная операция над обратимыми частями обфускатора. Он работает на уровне пула констант и инструкций, используя ту же модель BCEL, что и сам обфускатор, поэтому то, что он записывает обратно, — это ровно то, что ожидает JVM.

Четыре механизма, выполняемые конвейером `full` в этом порядке:

**1. Расшифровка строк (`DecryptorSimulator`).** Обфускатор заменяет каждую строковую константу на `ldc "шифртекст"` + `invokestatic DecryptString`. Деобфускатор находит методы-кандидаты по профилю инструкций (цикл XOR, AND с маской 63, построение массива символов, `charAt`), а затем делает то, чего не делает ни один наивный инструмент: **реально исполняет сгенерированный байткод дешифратора** на маленьком интерпретаторе стековой машины. Алгоритм не важен — какая бы арифметика ни была сгенерирована Allatori (вывод seed, цепочки XOR-ключей, маски), интерпретатор выполняет её и возвращает открытый текст. Место вызова переписывается на `ldc "открытый текст"` + `nop`, а когда ни одна «живая» инструкция больше не ссылается на класс дешифратора, класс удаляется. Дешифраторы, зависящие от значений времени выполнения, сообщаются как «остались зашифрованными», а не угадываются.

**2. Восстановление имён (`UnrenameTransformer`).** XML-маппинг (`<class old=... new=...>` с `<method old="имя(дескриптор)" new="n"/>` и `<field old="имя ТИП" new="n"/>`) управляет обратным переименованием на уровне пула констант: восстанавливаются `this_class`, `super_class` и интерфейсы, каждое объявление метода и поля возвращает исходное имя, и переписываются все ссылки (Methodref, Fieldref, InterfaceMethodref, их владельцы-классы и записи NameAndType) — включая владельцев, уже переписанных ранее в том же проходе. Записи JAR переиндексируются по восстановленным именам классов, поэтому возвращается исходная структура пакетов.

**3. Ремаппинг StackMapTable (`StackMapRemapper`).** Расшифровка строк укорачивает код (`invokestatic` 3 байта → `nop` 1 байт). Атрибут StackMapTable при перекодировании переносится дословно, поэтому его фреймы продолжали бы указывать в старую раскладку, и верификатор JVM (и `javap`) отверг бы класс. Ремаппер переписывает смещение каждого фрейма так, чтобы он указывал на ту же инструкцию в новой раскладке — включая смещения инструкций внутри верификационных записей `ITEM_Uninitialized`.

**4. Восстановление стек-трейсов (`restore-stacktrace`).** Читает тот же XML-маппинг (записи методов плюс список `<lines>` зашифрованных номеров строк) и построчно переписывает захваченный трейс: `at com.example.demo.h.K.K(K.java:7)` превращается в `at com.example.demo.App.crash(App.java:31)`.

**Честные ограничения.** Полное восстановление имён требует файла маппинга — без него обфускация по замыслу необратима, и работает только расшифровка строк (ей маппинг не нужен). Это и есть корректное поведение 1:1: с журналом, который написал обфускатор, восстанавливается всё, что он изменил; без него — только то, что можно вернуть без потери информации.

# Структура проекта

```
src/main/java/com/allatori/          обфускатор (оригинальная реимплементация)
src/main/java/com/allatori/deobfuscate/   деобфускатор
  Deobfuscate.java                   CLI + оркестрация конвейера
  MappingData.java                   разбор XML-журнала обфускатора
  UnrenameTransformer.java           обратное переименование на уровне пула констант
  StringDecryptorTransformer.java    поиск дешифраторов + перезапись мест вызова
  DecryptorSimulator.java            мини стековая машина, исполняющая байткод дешифратора
  StackMapRemapper.java              ремаппинг смещений StackMapTable после правок
demo/                                демо-приложение + конфиг для задач Gradle
tools/                               диагностические утилиты (DumpMain)
```

# Устранение неполадок

- PowerShell выводит шумный `NativeCommandError` для консольного вывода `java`/`gradlew`; ориентируйтесь на `BUILD SUCCESSFUL`, а не на код возврата.
- Системные свойства со значениями нужно брать в кавычки: `java "-Dallatori.deobfuscate.trace=true" ...`
- Отладочная диагностика расшифровки строк: `-Dallatori.deobfuscate.debug=true` (сводка) и `-Dallatori.deobfuscate.trace=true` (трассировка по опкодам в `DecryptorSimulator`).
